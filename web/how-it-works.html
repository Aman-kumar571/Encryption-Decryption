FileCrypt Browser Tool How It Works

How FileCrypt Works

FileCrypt uses established, standardized cryptography to encrypt and authenticate files. The desktop app and browser tool share the exact same format and specifications.

Encrypted File Layout (.fct)

Every encrypted file begins with a 32-byte header followed by AES-GCM ciphertext with an appended authentication tag:

Offset Length Description
0 - 3 4 bytes ASCII magic constant FCT1
4 - 19 16 bytes Cryptographically random salt
20 - 31 12 bytes Initialization Vector (IV / Nonce)
32+ Remaining AES-256-GCM ciphertext + 16-byte authentication tag

Key Derivation: PBKDF2-HMAC-SHA256

Passwords are never used directly as encryption keys. Instead, FileCrypt derives a 256-bit symmetric key using PBKDF2 with HMAC-SHA256 and 600,000 iterations. This high iteration count slows down brute-force and dictionary attacks significantly.

A fresh 16-byte random salt is generated for each file. This ensures that encrypting identical files or using identical passwords produces different keys and ciphertexts.

Authenticated Encryption: AES-256-GCM

FileCrypt uses AES in Galois/Counter Mode (GCM). GCM provides both confidentiality (keeping data secret) and integrity (ensuring data has not been modified). At the end of encryption, a 16-byte authentication tag is computed and appended to the ciphertext.

Authentication and Tamper Detection

During decryption, AES-GCM verifies the authentication tag before releasing decrypted plaintext. If a wrong password is provided, or if even a single byte of the file has been altered, the tag verification fails. In both cases, FileCrypt reports:

Wrong password, or the file is corrupted.

No partial plaintext or internal error details are exposed.

Cross-Platform Interoperability

Because the format relies strictly on standard specifications (AES-GCM and PBKDF2), any file encrypted with the desktop Java application can be decrypted in the browser, and vice versa.

Honest Limitations

  • No password recovery: There are no backdoors or master keys. If the password is forgotten, the data cannot be decrypted.
  • File metadata: Only file contents are encrypted. File names and file creation dates are not concealed by the encryption process.
  • Browser memory boundaries: The browser tool operates entirely in memory using WebCrypto Blobs, making files larger than 100 MB impractical for browser decryption. Use the desktop application for large files.
  • Educational project: FileCrypt has not been audited by third-party security researchers. It is intended for educational purposes.
